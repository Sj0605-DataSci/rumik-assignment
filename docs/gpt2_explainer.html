01

Codebase map

Five files. No file imports torch or jax. backend.py is the only place that ever mentions cupy by name — everywhere else just uses whatever self.xp was handed at construction time.

FileWhat lives there
backend.py get_xp(device) returns the numpy or cupy module itself. scatter_add() is the one function where the two backends diverge (np.add.at vs cupyx.scatter_add) because gradient accumulation at repeated embedding indices isn't expressible identically in both APIs.
param.py Param: a trainable array (.data) plus its gradient buffer (.grad), which backward passes always accumulate into with +=, never overwrite — this is what makes the tied embedding table's two gradient sources merge instead of clobber.
layers.py Every layer as a class with hand-coded forward() / backward(): Linear, LayerNorm, GELU, Embedding, CausalSelfAttention, MLP, Block, plus the free functions softmax, softmax_backward, softmax_cross_entropy. No autograd tape — each layer caches whatever its own backward needs on self.
model.py GPTConfig (the five architecture numbers) and GPT, which wires the embeddings + N blocks + final LayerNorm + tied output projection into the fixed pipeline traced in §5, and owns the one non-layer-local piece of backward math: the weight-tying gradient merge.
optim.py AdamW and cosine_lr() — pure parameter-update arithmetic, no forward/backward involved at all.

06

Math reference

Every function with a nontrivial derivative, its forward formula, the backward gradient actually coded in layers.py, and the numerical-stability "ceiling" that keeps it from overflowing or dividing by zero at the extremes.

Linear layers.py — Linear

forward y = x·W + b
backward dx = dy·Wᵀ dW = xᵀ·dy (flattened over B·T) db = Σ dy (summed over B·T)

LayerNorm layers.py — LayerNorm

forward, normalizing over the last axis (size n = C) μ = mean(x) σ² = mean((x−μ)²) x̂ = (x−μ) / √(σ²+ε) y = γ·x̂ + β
backward dγ = Σ(dy · x̂) dβ = Σ dy dx̂ = dy · γ dx = [ n·dx̂ − Σdx̂ − x̂·Σ(dx̂·x̂) ] / (n·σ)
Ceiling: ε=1e-5 inside the square root prevents divide-by-zero when a token's activations are (near-)constant across the C axis. The backward divides by σ a second time — same guard needed there, easy to forget since it's not visually adjacent to the epsilon in the forward pass.

GELU (tanh approximation) layers.py — GELU

forward — GPT-2's exact approximation, c = √(2/π) inner = c·(x + 0.044715·x³) t = tanh(inner) y = 0.5·x·(1+t)
backward — product + chain rule through tanh d(inner)/dx = c·(1 + 3·0.044715·x²) dy/dx = 0.5·(1+t) + 0.5·x·(1−t²)·d(inner)/dx dx = dy_upstream · dy/dx

Embedding lookup layers.py — Embedding

forward — row gather y = table[idx]
backward — scatter-add, NOT scatter-assign dtable[idx] += dy (accumulate; np.add.at / cupyx.scatter_add)
Ceiling: not a numerical one, a correctness one — the same token id can appear more than once in a batch, and a plain dtable[idx] = dy would let the later occurrence silently overwrite the earlier one's gradient instead of summing them. Verified directly in tests/test_gradients.py by forcing a duplicate index.

Softmax layers.py — softmax / softmax_backward

forward s = exp(x − max(x)) / Σ exp(x − max(x))
backward — contracted Jacobian, never materialized ds = s · (dy − Σ(dy·s))
Ceiling: subtracting max(x) before exponentiating caps the largest exponent argument at 0, so exp() can never overflow float32/float64 range regardless of how large the raw logits get — shifting doesn't change the result since it cancels in the ratio. The backward form deliberately avoids building the full T×T Jacobian per head; it contracts directly with the upstream gradient.

Causal self-attention layers.py — CausalSelfAttention

forward, per head att = (q·kᵀ) / √hd + mask p = softmax(att, axis=-1) y = p·v
backward dp = dy·vᵀ dv = pᵀ·dy datt = softmax_backward(p, dp) · (1/√hd) dq = datt·k dk = dattᵀ·q
Ceiling: the causal mask adds −inf to future positions before the softmax, which drives their probability to exactly 0 (not just small) — so their gradient contribution through softmax_backward is exactly 0 too, with no leakage from masked-out future tokens back into q/k. No separate masking step is needed in the backward pass; it falls out of the math for free.

Softmax cross-entropy layers.py — softmax_cross_entropy

forward — computed via log-sum-exp, not via softmax then log shifted = logits − max(logits) logprobs = shifted − log(Σ exp(shifted)) loss = mean( −logprobs[i, target_i] )
backward — the combined closed form, derived once dlogits = softmax(logits) dlogits[i,target_i] −= 1 dlogits /= N
Ceiling: computing loss through log-sum-exp rather than log(softmax(x)) avoids ever taking log of a near-zero probability. And the combined gradient softmax(x) − one_hot(target) is used directly instead of differentiating softmax and negative-log-likelihood as two separate steps — that separate path would divide by the predicted probability somewhere, which is exactly the quantity that can be closest to zero for a wrong, confident early-training prediction.

Weight tying model.py — GPT.backward

Not a single function, but a wiring detail worth its own entry: wte.weight is read twice per forward pass — once as the embedding table, once (transposed) as the output projection — so it must be written twice per backward pass, and both writes have to add rather than replace.

07

AdamW — pure update math, no backward involved

Once every Param.grad is populated, the optimizer never touches forward or backward again — it's just the update rule from the paper, applied array-by-array.

optim.py — AdamW.step, per parameter m = β₁·m + (1−β₁)·g v = β₂·v + (1−β₂)·g² m̂ = m / (1−β₁ᵗ) v̂ = v / (1−β₂ᵗ) if ndim ≥ 2: θ −= lr·λ·θ (decoupled weight decay) θ −= lr · m̂ / (√v̂ + ε)
Ceiling: ε=1e-8 in the denominator prevents a division blow-up when a parameter's gradient variance estimate v̂ is still near zero, which happens routinely in the first few steps before the exponential moving averages have accumulated enough history. Weight decay is skipped for 1-D parameters (LayerNorm's γ/β, every Linear bias) — decaying a bias or a norm gain toward zero has no regularizing justification the way decaying a weight matrix does.

Gradient clipping sits just before this, in train.py: the global L2 norm across every parameter's gradient is computed, and if it exceeds 1.0, every gradient is rescaled by max_norm / total_norm — a ceiling on how far a single noisy batch can move the parameters in one step.
